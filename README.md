# Code Rumble · 문제집·결승 규칙 개정판

재업로드한 문제집의 25문제를 모두 읽고 레벨을 배정했습니다. 럼블 25문제와 서로 다른 결승 신작 10문제, 유형·로직 힌트, 숨은 테스트를 제공합니다. 배정표는 `docs/source-check.md`에서 확인하세요.

**처음 적용할 때는 [START-HERE.md](START-HERE.md)를 위에서부터 따라 하세요.** 채점·AI 조언·팀 로고에 같은 OpenAI API 키를 사용합니다.

5팀 × 5명, 럼블 5라운드와 결승 1경기를 운영합니다. 프론트엔드는 Netlify, 백엔드는 Render 또는 로컬 Python에서 실행합니다. Python 3.10 이상이며 외부 Python 패키지는 필요하지 않습니다.

## 이번 버전으로 바꾸기

**기존 `static/config.js`에 입력한 실제 Render 주소를 반드시 보관하세요.** 새 압축본의 config.js는 로컬 실행을 위해 빈 값입니다. 덮어쓴다면 실제 주소를 다시 입력해야 합니다.

이번에는 프론트엔드와 백엔드가 모두 변경되었습니다. 저장소에 `*.py` 전체, `source_cases.json`와 `problem_figures.json`, `assets/`, `logo_prompt.txt`, `static/`와 배포 설정을 함께 올리고 Render와 Netlify를 모두 재배포하세요. 오래 열린 브라우저는 Ctrl+Shift+R로 새로고침하세요. 진행 중인 대회 도중에는 버전을 바꾸지 말고 새 대회 시작 전에 적용하세요. 영속 디스크의 기존 사용자와 팀 설정은 유지하지만 규칙과 문제 구성이 달라졌으므로 운영자 화면에서 새 대회 시작 시 전체 초기화를 권장합니다.

## 로컬에서 전체 기능 시험하기

```bash
python server.py
```

Windows에서는 `py -3 server.py`도 가능합니다. http://127.0.0.1:8765 에 접속하세요. 첫 실행 후 `data/access.json`의 admin 코드는 운영자용, teams 아래 code는 선수용입니다. 각 탭에 다른 코드로 로그인할 수 있습니다.

**이 버전은 공개 Render 서버에서 OpenAI 채점에 연결됩니다.** `JUDGE_PROVIDER=openai`와 `OPENAI_API_KEY`를 설정해야 합니다. 제출 코드는 OpenAI의 새 컨테이너에서 실행되며 Render의 Python으로 실행하지 않습니다. 로컬 환경은 기본적으로 기존 로컬 채점기를 사용합니다. 실제 API 키가 제공되지 않아 유료 API의 실연결 검증은 하지 못했습니다. 운영자 연결 시험과 25명 동시 제출 리허설을 마친 뒤 대회를 진행하세요.

채점 실행 도구 호출이 정확히 1회인지, 지정한 명령·컨테이너가 일치하는지, 실행 로그에 요청별 식별값과 모든 테스트 결과가 있는지를 검사합니다. 모델의 자연어 판정은 사용하지 않습니다. 정답과 모범 코드는 서버에 보관하며 실행 컨테이너에는 전달하지 않습니다. 제출마다 새 컨테이너를 만들고 종료 시 삭제를 요청합니다. 삭제가 실패하면 컨테이너 만료 정책이 적용됩니다. 실행 환경의 네트워크는 비활성화합니다.

API 실패·검증 실패에는 점수·오답 기록·10초 대기시간을 적용하지 않고 오류를 계속 표시합니다. 공개 서버가 로컬 채점으로 자동 전환되는 일은 없습니다. 컨테이너 생성과 업로드는 각 30초, 실행 API는 최대 90초를 기다립니다. 정상 응답 속도를 보장하는 수치는 아닙니다. 원격 채점의 선착순도 **서버가 채점 완료를 승인한 시각** 기준이고, 경기 종료 뒤 도착한 결과는 점수에 반영하지 않습니다. 제출 직전 마감과 API 지연이 순위에 영향을 줄 수 있으므로 리허설에서 반드시 확인하세요.

## 참가 및 운영 순서

1. 참가자는 자신의 코드로 입장해 이름을 정합니다. 팀장이 없으면 팀장 체크박스가 표시됩니다. 앞선 네 명이 팀장을 선택하지 않았다면 마지막 선수에게 자동 지정됩니다.
2. 팀장은 팀명과 로고를 확정합니다. 이미 접속한 선수들도 이후 변경된 팀명을 보게 됩니다.
3. 운영자 화면은 **대진·준비 확인** 단계로 시작합니다. 양 팀 로고와 이름, 팀원, 선택 레벨, 접속 상태, 준비 상태가 표시됩니다. 참가자는 레벨을 고르고 **준비 완료**를 누릅니다. 미선택은 시작 시 무작위 배정됩니다. 선택을 바꾸면 준비가 해제됩니다.
4. 해당 라운드에 경기하는 모든 팀원이 준비해야 운영자가 **라운드 시작**을 누를 수 있습니다. 휴식 팀의 준비는 필요하지 않습니다.
5. 럼블은 5분, 결승은 10분입니다. 서버 타이머가 자동 종료하며, 운영자는 먼저 종료할 수도 있습니다. 운영자 화면을 닫아도 타이머는 서버에서 진행됩니다.
6. 럼블 종료 후 **결과 확인** 단계에서 승패와 보너스를 확인합니다. **결과 확인 완료 · 다음 대진 열기**를 눌러 다음 준비 화면으로 이동합니다. 준비 확인 없이 연속 시작되지 않습니다.
7. 5라운드 결과까지의 누적 승점 상위 두 팀이 결승에 갑니다. 결승 진출 경계의 **누적 승점 동점**은 운영자가 대회 밖에서 결정한 진출팀을 지정해야 합니다. 결승이 끝나면 대회가 종료되며 다음 라운드는 없습니다.

## 운영자 혼자 진행하는 리허설

첫 라운드의 대진·준비 확인 화면에서 **리허설 켜기**를 누릅니다. 이 기능은 첫 라운드를 시작하기 전까지만 바꿀 수 있습니다. 이미 진행 중인 대회를 혼자 처음부터 시험하려면 운영자 화면의 **전체 초기화**를 먼저 실행합니다. 초기화하면 기존 이름, 팀명, 로고, 경기 기록이 삭제되며 접속 코드는 유지됩니다.

1. 선수 이름·팀명·로고·준비 상태를 설정하지 않아도 **라운드 시작**을 누를 수 있습니다. 서버가 각 팀의 미접속 선수 5명에게 레벨 1~5를 배정합니다.
2. 각 매치 아래에서 팀과 레벨을 골라 **정답 처리** 또는 **오답 연출**을 누릅니다. 정답은 실제 승점·solve 잔액·선착/후착·승패에 반영됩니다. 오답은 제출 기록과 화면 효과를 시험합니다. 같은 선수의 정답 중복 처리는 막습니다.
3. **현재 라운드 종료**를 눌러 매치를 일찍 마치고 경기 결과와 다음 대진을 확인한 뒤 **결과 확인 완료 · 다음 대진 열기**를 누릅니다. 이 과정을 럼블 5라운드까지 반복합니다. 시간을 기다리면 자동 종료됩니다.
4. 결승 진출 경계에 누적 승점 동점이 있으면 **결승 진출 동점 결정**에서 합의한 두 팀을 확정합니다. 1위가 단독인 경우 1위 팀은 반드시 포함합니다. 확정 전에는 다음 대진을 열 수 없습니다. 무승부만 다섯 라운드 진행했다면 다섯 팀 모두 후보가 됩니다.
5. 결승도 각 레벨의 정답 처리로 승점을 쌓습니다. Lv5를 해결해도 경기는 계속됩니다. 10분 만료 또는 운영자의 라운드 종료 시 결승 승점 합이 큰 팀이 승리합니다.

리허설 판정은 운영자가 게임 흐름을 시험하기 위한 기록입니다. 정답 처리는 제출 코드의 실행이나 실제 채점이 아니며 제출 코드 칸에는 리허설 표시만 기록합니다. OpenAI 호출과 비용도 발생하지 않습니다. 실제 제출·AI 조언·로고 생성은 기존 방식으로 별도 시험하세요. 리허설 종료 후 실제 대회를 열기 전에는 **전체 초기화**로 기록과 리허설 설정을 지우세요. 이 모드는 운영자 권한으로만 켜고 조작할 수 있습니다.

오답·실행 오류·시간 초과 판정은 10초 동안 재제출을 막습니다. 코드 편집과 자동 저장은 가능하고 제출 버튼 옆에 남은 시간이 표시됩니다. 새로고침하거나 API를 직접 호출해도 서버가 대기시간을 확인합니다. 정답은 서버 검증이 끝나 경기 종료 전에 승인되어야 점수로 인정됩니다.

## 점수와 아이템

| 레벨 | 럼블 선착 승점 | 럼블 후착 승점 | 정답 solve |
|---|---:|---:|---:|
| 1 | 100 | 50 | 100 |
| 2 | 150 | 75 | 150 |
| 3 | 200 | 100 | 200 |
| 4 | 250 | 125 | 250 |
| 5 | 300 | 150 | 300 |

럼블의 상대 팀은 같은 문제를 받습니다. 서로 다른 두 매치에도 해당 라운드의 같은 세트를 제공합니다. 다섯 라운드는 각각 다른 5문제를 사용합니다. 승점이 높은 팀이 매치에서 이기고 **팀 승점에 100점**을 추가로 받습니다. 개인 승점에 배분하거나 solve포인트로 지급하지 않습니다. 동점은 무승부이며 보너스가 없습니다. 정답 solve는 같은 매치에서 즉시 팀 공용으로 사용할 수 있습니다.

| 구매 항목 | solve 소모 |
|---|---:|
| 문제 유형 | 50 |
| 핵심 구조 | 150 |
| 현재 코드 AI 조언 | 300 |

현재 결승에서도 위 힌트 가격을 동일하게 적용합니다. 힌트는 각 선수·문제·종류별 한 번 구매하며 재조회에는 비용이 들지 않습니다. AI 호출 실패, 경기 종료 후 도착한 AI 응답에는 차감하지 않습니다. 동시에 요청한 구매는 서버가 잔액을 다시 확인합니다.

## 운영자 관전 화면

- 각 매치의 양 팀 로고·팀명·개인별 레벨·개인 승점·정답 여부·구매한 힌트 종류와 비용을 표시합니다.
- 파랑·분홍 승점 게이지가 정답으로 획득한 점수에 따라 움직입니다. 초기값은 50:50입니다. 결과에는 승리 보너스를 따로 표시합니다.
- 오답은 선수 카드의 흔들림과 붉은 효과, 결승 스킬은 빙결·교란·절단 효과로 표시합니다. 승패는 모든 참가자의 결과 화면과 운영자 팀 로고 옆에 표시합니다. 모션 줄이기 설정이 켜진 브라우저에서는 애니메이션을 줄입니다.
- **코드 확인**은 문제와 작성 중인 코드, 마지막 제출 코드, 정답 제출 코드를 선택해 보여줍니다.
- **실시간 코드 비교**는 매치와 레벨을 선택해 양 팀 코드를 나란히 표시합니다. 다른 줄에 색을 칠합니다. 실시간은 WebSocket이 아닌 자동 저장 후 약 1~2초 갱신 방식입니다. 네트워크가 느리면 더 늦어질 수 있습니다.
- 선수는 상대의 코드나 숨겨진 테스트를 받을 수 없으며, 코드 열람 API는 운영자 권한을 검사합니다. 참가 화면에는 운영자 코드 관전 사실을 안내합니다.

## 결승 규칙

결승은 10분 동안 획득한 **결승 승점 합**으로 승패를 결정합니다. 럼블 누적 승점과 럼블 승리 보너스는 결승 점수에 더하지 않습니다. 팀 공용 solve 잔액은 그대로 이어서 사용합니다.

양 팀은 서로 다른 문제를 풀며, 결승에서는 제출 순서와 관계없이 Lv1~5 승점 100, 150, 200, 250, 300점을 받습니다. 정답 solve도 같은 금액을 전액 받습니다. 승점 합이 같으면 경기 종료 시 남은 팀 공용 solve포인트가 더 많은 팀이 승리합니다. 이 잔액에는 럼블에서 이어받은 금액, 결승 정답 보상, 힌트 사용 비용이 모두 반영됩니다. 승점과 잔액이 모두 같으면 무승부입니다. 결승에는 승리 보너스 100점을 더하지 않습니다. Lv5 정답으로 조기 종료하지 않습니다.

Lv4와 Lv5는 독립 문제입니다. 결승은 제공된 럼블 문제 유형을 확장한 신작 10문제로 교체했습니다. Lv4는 정확한 선택 개수 제약, Lv5는 네 구간 비용 최적화 또는 원형 인접 제약을 추가했습니다. 두 팀의 세부 문제는 다르며 실제 풀이 시간의 균형은 리허설로 확인하세요.

결승 레벨 1~3 정답자는 완료 화면에서 스킬을 **각자 한 번**, solve 소모 없이 사용할 수 있습니다.

| 클리어 레벨 | 스킬 | 대상·효과 |
|---|---|---|
| 1 | 빙결 | 상대 5명 전체의 문제를 가리고 코드 편집·제출을 20초 중지 |
| 2 | 변수 교란 | 상대 Lv4·5의 가장 많이 등장한 변수 이름을 무작위 영문 10자로 변경 |
| 3 | 코드 절단 | 상대 Lv4·5 코드에서 아래쪽부터 찾은 마지막 내용 있는 두 줄 삭제 |

변수 교란은 문자열·주석·객체 속성 이름을 제외합니다. 동률 변수는 이름순으로 고르며 바꿀 변수가 없으면 코드가 그대로여도 스킬은 소모됩니다. 작성 중이라 문법이 완성되지 않은 코드는 토큰 기준으로 가능한 변수 후보를 판별합니다. 코드 절단은 공백 줄을 건너뛰고 내용이 있는 두 줄을 삭제합니다. 주석도 내용이 있는 줄입니다. 내용 있는 줄이 하나뿐이면 그 한 줄만 삭제합니다. 이미 제출되어 채점 중인 코드는 제출 당시 스냅샷을 채점하며 나중의 스킬로 바뀌지 않습니다.

코드 자동 저장에는 버전 번호가 있습니다. 스킬과 자동 저장이 경합하면 서버의 스킬 적용 버전이 우선합니다. 아직 서버에 저장되지 않은 입력은 해당 브라우저 sessionStorage의 `:before-effect` 키로 보관하지만 자동 복원하지 않습니다. 정식 운영 전 여러 브라우저의 동시 입력·아이템 사용을 꼭 시험하세요.

## 초기화 시점

**운영자의 로그인·재접속 자체는 초기화하지 않습니다.** 다음 라운드 준비도 팀 이름과 누적 점수·잔액을 유지합니다.

- 운영자의 **전체 초기화** 버튼을 누르고 `전체 초기화`를 입력하면 팀명·로고·팀장·선수 이름·준비·코드·제출·아이템·포인트·모든 경기·리허설 모드·결승 진출팀 선택을 초기화합니다. 접속 코드는 유지합니다.
- 로컬은 `data/`를 지우지 않는 한 서버 재실행 후에도 유지합니다. 유료 Render 영속 디스크도 마찬가지입니다.
- **무료 Render는 잠들거나 재시작·재배포될 때 SQLite가 사라질 수 있습니다.** 이것은 운영자 로그인 로직이 아닙니다. 같은 ACCESS_SEED를 유지하면 접속 코드는 같지만 게임 데이터는 새로 시작합니다.

## OpenAI API 사용료 결제와 키 적용

API 키 자체를 구매하는 것이 아니라 **OpenAI API 사용량을 결제하고 키를 발급**합니다. 이 프로젝트는 ChatGPT 화면에 로그인해 사용하는 방식이 아닙니다. API 결제 화면에서 별도로 결제 상태를 확인하세요.

1. https://platform.openai.com 에 로그인합니다. 이 프로젝트에 사용할 Project를 생성하거나 선택합니다.
2. Settings에서 Billing을 열고 결제 수단을 등록한 뒤 API 크레딧을 충전하거나 계정에 제공되는 결제 방식을 설정합니다. 최소 충전 금액과 세금은 결제 화면에 표시된 값을 따르세요. 필요하지 않으면 자동 충전은 켜지 않아도 됩니다.
3. API Keys 화면(https://platform.openai.com/api-keys)에서 새 Secret Key를 만듭니다. 생성 직후 안전한 곳에 보관하세요. 공개 저장소·브라우저 코드·스크린샷에 노출하지 마세요.
4. Render → 해당 백엔드 서비스 → Environment에 아래 값을 추가하고 저장·재배포합니다. Netlify에는 키를 넣지 않습니다.

| 환경 변수 | 값 |
|---|---|
| OPENAI_API_KEY | 발급받은 비밀 키 |
| JUDGE_PROVIDER | openai |
| OPENAI_JUDGE_MODEL | gpt-4.1-mini |
| OPENAI_MODEL | gpt-4.1-mini (현재 코드 조언 기본값) |
| OPENAI_IMAGE_MODEL | gpt-image-2.5-flare (현재 로고 기본값) |

계정에서 해당 모델을 사용할 수 없으면 모델 접근 권한·결제·이미지 조직 인증 요구 여부를 확인하세요. 모델 이름만 바꿀 때는 해당 모델이 `/v1/responses` 또는 이미지 생성 API를 지원하는지도 확인해야 합니다. 배포 설정 파일의 기존 `OPENAI_IMAGE_MODEL=gpt-image-1` 값도 새 기본값으로 업데이트하세요.

5. 운영자 화면에서 `채점·AI 조언 연결 시험 (유료 호출)`을 실행합니다. 정답·오답·실행 오류 판정과 AI 조언을 검사하고 소요 시간을 표시합니다. 실패하면 이후 시험을 중단할 수 있습니다. 실제 OpenAI 사용료가 발생하며 게임 점수에는 반영하지 않습니다. 이어서 팀장으로 새 팀명을 저장하고 로고 후보 생성 버튼을 눌러 시험합니다. AI 조언은 팀 solve 잔액이 300점 이상이고 진행 중인 문제에서 사용할 수 있습니다. 현재 OpenAI 키가 없는 환경에서는 실제 유료 API 호출은 시험하지 않았으며, 로컬 가짜 응답 테스트로 통신 처리를 확인합니다.
6. OpenAI Usage와 Billing에서 사용량을 확인합니다. 지출 한도와 크레딧 잔액을 설정하고 운영 전 적은 횟수로 먼저 시험하세요. API 제한·잔액 부족·권한 오류일 때는 기능이 실패할 수 있습니다.

공식 참고: [빠른 시작](https://developers.openai.com/api/docs/quickstart), [이미지 생성](https://developers.openai.com/api/docs/guides/image-generation), [지출 한도](https://developers.openai.com/api/docs/guides/spend-limits).

## 로고 후보와 30초 목표

기본값은 빠른 이미지 모델, `quality=low`, `1024x1024`, JPEG 압축 65이며 후보 3개를 한 번 요청합니다. 서버는 백그라운드에서 생성하고, 경기 API를 기다리게 하지 않습니다. 이미지는 상태 JSON에 반복해서 넣지 않고 이미지 URL로 전달합니다.

생성 시작 시 임시 후보 세 개를 준비합니다. AI가 먼저 끝나면 AI 후보로 교체합니다. **30초가 지나도 응답이 없으면 임시 후보 선택 버튼을 활성화**하여 입장할 수 있게 합니다. 이후 선택 전 AI가 완료되면 후보가 바뀝니다. 이미 임시 로고로 확정했다면 뒤늦은 AI 응답으로 팀 로고를 바꾸지 않습니다. API 실패 시에도 임시 후보를 고를 수 있습니다. 실제 OpenAI 처리 시간을 제어할 수 없으므로 AI 이미지 3개가 반드시 30초 안에 생성된다고 보장하지 않습니다. 요청이 서버에서 진행된 경우 UI에서 임시 로고를 선택했어도 API 사용량이 발생할 수 있습니다.

첨부한 팀로고.zip의 30개 원본을 확인하여 `assets/logo-references/`에 보관했습니다. 파일명과 한국어 별칭은 `teams.json`, 설명은 `docs/logo-reference-guide.md`에 있습니다. 30개 모두를 담은 두 장의 참고 시트를 `/v1/images/edits` 요청에 실제로 첨부합니다. 프롬프트는 `logo_prompt.txt`를 사용하며 영어·한국어 팀명 대응도 전달합니다. 이는 요청마다 이미지를 참조하는 방식이며 모델 재학습·파인튜닝은 아닙니다.

## Netlify + Render 무료 배포

현재 `render.yaml`은 `plan: free`입니다. 별도 디스크를 생성하지 않습니다. `render-paid.yaml`은 선택 가능한 유료 저장소 구성으로 기본 배포에 사용되지 않습니다.

Git 저장소 루트에 모든 Python 파일과 `static/`, `netlify.toml`, `render.yaml`을 올립니다. Netlify 게시 폴더는 `static`, 빌드 명령은 없습니다. 기존 Render 서비스의 Environment에서 `FRONTEND_ORIGIN`에 실제 Netlify 주소를, `ACCESS_SEED`에 32자 이상의 비밀값을 입력합니다.

```powershell
# 비밀값을 새로 만들어야 하는 경우에만 실행
py -3 -c "import secrets; print(secrets.token_urlsafe(32))"
# Render와 같은 값 사용
$env:ACCESS_SEED = 'Render와 같은 비밀값'
py -3 access_codes.py
```

`static/config.js`에는 실제 Render 주소만 넣습니다.

```js
window.RUMBLE_API_BASE_URL = 'https://실제서비스.onrender.com';
```

무료 Render에는 Shell이 없으므로 위 로컬 명령으로 코드를 확인합니다. Render와 로컬 ACCESS_SEED가 다르면 코드도 다릅니다. 결제 수단을 등록한 Render 계정은 무료 플랜도 트래픽·빌드 포함량 초과분이 청구될 수 있으므로 사용량 설정을 확인하세요. 공개 운영에 필요한 영속 데이터와 격리 채점기는 이 무료 설정만으로 제공되지 않습니다.

## 문제 파일과 확인

럼블 25개와 결승 A/B 10개, 총 35개입니다. 이전에 학습한 순회·문자열·스택·큐·슬라이딩 윈도우·DFS/BFS·부분집합·트리·힙·이진 탐색·최단 경로 유형으로 구성했습니다. 기존 SWEA 지문을 복제한 것은 아닙니다.

- `problems.py`: 공통 채점 형식과 제한된 공개 예제.
- `rumble_bank.py`: 럼블 25문제, 힌트, 모범 코드와 테스트. `source_cases.json`와 `problem_figures.json`: 원본 예제 검증 자료.
- `final_bank.py`: 결승 A/B 10문제, 풀이, 힌트, 테스트 입력.
- `docs/questions/`, `docs/answers/`, `docs/hints/`, `docs/tests/`: 문제별로 분리한 문서.
- `python export_problem_files.py`: 현재 서버 데이터로 문서를 다시 생성합니다.
- `docs/problem-book.md`: 운영자용 전체 문제, 예제, 유형·구조 힌트, 정답 코드.
- `docs/test-cases.json`: 운영자용 숨은 테스트 입력과 정답. Netlify의 static 안에 넣지 마세요.

SWEA 형식으로 첫 줄 T, 출력 `#tc 정답`을 사용합니다. `input()`으로 읽을 수 있고 `sys.stdin = open(...)`은 필요하지 않습니다.

```bash
python -m unittest discover -s tests -v
node tests/test_frontend.js
```

통합 테스트는 5라운드와 결승 전체, 준비 제한·즉시 포인트·승리 보너스 중복 방지·10초 제한·코드 열람 권한·아이템·코드 버전 충돌·결승 점수 합산·초기화를 검사합니다. 결승 Lv4·5에는 별도의 검증 알고리즘도 사용합니다.

검증 범위: Python 자동 테스트 15개와 Node 프론트엔드 로직 검사를 통과했습니다. 운영자 단독으로 5라운드와 결승까지 진행하는 서버 통합 시험도 포함했습니다. 실제 브라우저 클릭·화면 배치 검증은 수행하지 못했습니다. OpenAI 호출은 가짜 응답으로 검사했으며, 실제 키 연결 후 운영자 연결 시험, 로고 생성, 동시 제출 리허설을 진행하세요. 모델이 지정한 실행 명령을 바꾸면 오채점 대신 서비스 오류로 처리됩니다.

이전 버전의 `AI가 지정한 실행 명령을 그대로 수행하지 않아 판정을 보류했습니다` 오류가 나타나면 [START-HERE.md](START-HERE.md)의 2026-09-28 수정 안내를 따르세요.
