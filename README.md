# CODE RUMBLE — 대회 프로토타입

5팀 × 5명, 럼블 5라운드(총 10매치)와 결승 단판을 진행하는 알고리즘 대회입니다. Python 3.10 이상만 있으면 실행됩니다. 외부 패키지 설치는 필요하지 않습니다.

## 바로 실행

압축 파일을 풀고 `code-rumble` 폴더에서 실행합니다.

```bash
python server.py
```

Windows에서 `python` 명령이 안 되면 PowerShell에서 `py -3 server.py`를 실행하세요. 브라우저에서 **http://127.0.0.1:8765**를 엽니다.

첫 실행 시 `data/access.json`이 자동 생성됩니다. 파일 안의 `admin` 코드는 운영자 화면, `teams` 아래의 `code`는 선수 화면에 입력합니다. 이 파일을 참가자 전체에게 공유하지 말고 각 선수에게 자기 코드만 전달하세요. 종료는 실행 중인 터미널에서 Ctrl+C입니다. 진행 데이터를 처음부터 다시 만들려면 서버를 종료하고 `data` 폴더를 삭제한 뒤 재시작하세요.

**이전 버전에서 갱신할 때는 서버를 반드시 종료하고 다시 실행하세요.** 기존 데이터에 20분 제한으로 시작된 경기가 있어도 재시작 시 시작 시각 기준 5분으로 보정합니다. 예전 단일 테스트케이스 형식으로 진행하던 아주 초기 버전의 데이터라면 `data` 폴더를 지우고 새 대회를 시작하세요.

서버는 `127.0.0.1`에만 접속을 받습니다. 같은 컴퓨터의 여러 브라우저 탭에서 참가 코드를 달리 입력하면 대회를 직접 시험할 수 있습니다. 한 탭의 로그인은 그 탭에만 저장됩니다.

## 진행 순서

1. 선수별 참가 코드로 접속하면 처음 한 번 이름을 설정합니다. 팀장이 없다면 **팀장 맡기**를 체크할 수 있습니다. 앞선 네 선수가 팀장을 선택하지 않았다면 다섯 번째 선수에게 자동으로 팀장 역할이 지정됩니다. 같은 팀 안에서 이름은 중복될 수 없습니다. 팀장은 대기실에 들어가기 전에 팀명을 정하고 로고 후보 세 개 중 하나를 확정합니다. 팀장을 먼저 정한 경우 다른 팀원도 접속할 수 있습니다.
2. 대기실에는 자신의 팀과 다음 상대 팀이 좌우로 표시됩니다. 라운드를 시작하기 전에 선수들이 드롭다운에서 **다음 경기 레벨**을 선택합니다. 같은 팀원이 이미 고른 레벨은 선택할 수 없습니다. 선택하지 않은 레벨은 라운드 시작 때 미선택 팀원에게 무작위로 배정됩니다. 쉬는 팀은 그 라운드의 문제를 배정받지 않습니다. 결승 레벨은 5라운드를 종료한 뒤 두 진출팀이 선택할 수 있습니다.
3. 운영자 코드로 접속해 **럼블 1라운드 시작**을 누릅니다. 각 팀의 해당 레벨 선수에게 같은 문제가 보입니다. 문제는 SWEA처럼 첫 줄의 테스트케이스 수 `T`를 읽고 `#1 정답`, `#2 정답` 형식으로 출력합니다.
4. 첫 정답 제출 팀은 그 레벨 배점의 100%, 상대 팀이 나중에 정답을 내면 50%를 승점으로 받습니다. 문제를 푼 팀은 온전한 배점만큼 solve포인트를 **즉시** 얻습니다. 팀원 누구나 같은 라운드에서 그 포인트로 힌트를 살 수 있습니다. 중복 정답 제출이나 같은 힌트 재조회에는 다시 보상하거나 과금하지 않습니다.
5. 5라운드가 끝나면 누적 럼블 승점 상위 두 팀이 결승에 진출합니다. 동률은 럼블 매치 승리 수 → 정답 수 → 팀 번호 순서로 정합니다. 결승 승점이 동률이면 운영자가 재경기/공동 우승 여부를 정해야 합니다.

매 라운드에 매치 2개가 동시에 열리고 1팀은 쉽니다. 두 매치의 레벨별 문제는 그 라운드에 동일합니다. 문제 세트는 **1 → 2 → 3 → 1 → 2 → 결승 3**으로 재사용하므로, 실제 경쟁 행사 전에 새 문제 세트를 추가해야 합니다. 결승의 승점은 럼블 순위에 합산되지 않습니다.

각 매치의 제한시간은 **5분**입니다. 정답을 맞힌 선수는 경기 종료 때까지 제출 완료 화면을 보며, 그 뒤 **대기실로 돌아가기** 버튼을 누를 수 있습니다. 시간 내에 정답을 맞히지 못한 선수는 종료 안내를 10초간 본 뒤 대기실로 자동 이동합니다. 운영자는 다음 라운드를 수동으로 엽니다.

코드 편집기에는 Python 구문 색상과 줄 번호가 있습니다. 변수 이름이나 기본 함수·메서드를 입력하다가 제안이 보이면 `Tab`으로 완성할 수 있습니다. 제안이 없을 때 `Tab`은 네 칸 들여쓰기이며, `if ...:` 또는 `for ...:` 뒤에서 `Enter`를 누르면 다음 줄을 자동 들여씁니다. `(`, `[`, `{`를 입력하면 대응하는 닫는 괄호가 생기고 커서는 두 괄호 사이에 놓입니다.

별도의 `input.txt` 파일은 만들지 않아도 됩니다. 채점기가 테스트 입력을 표준 입력으로 전달하므로 `input()`이나 `sys.stdin.readline()`을 그대로 사용할 수 있습니다. `import sys` 및 `sys.stdin = open("input.txt", "r")`은 필수가 아닙니다. 실행 중 오류가 나면 종료 코드와 Python traceback이 제출 결과에 남고, 화면이 갱신되거나 새로고침되어도 마지막 제출 결과가 유지됩니다.

## 문제와 배점

각 세트에 레벨 1~5 문제가 하나씩, 총 15개의 새 문제가 있습니다. 문제/예제/추가 케이스/정답 코드/힌트는 `problems.py`에 있습니다. 선수 화면에는 문제, 배점, 예제만 전달됩니다.

| 세트 | Lv1 | Lv2 | Lv3 | Lv4 | Lv5 |
|---|---|---|---|---|---|
| 1 | 충전 기록 | 보관함 잠금 로그 | 폐쇄된 통로 | 작업 시간표 | 가장 싼 도로 |
| 2 | 첫 중복 신호 | 연속 보급 구간 | 분리된 기지 | 교환권 최소 사용 | 작업 순서 결정 |
| 3 | 연결하지 않은 전구 | 돌아가는 인쇄 대기열 | 목표 합 짝 | 병력 합치기 | 기지 연결 비용 |

이번 변경에서 문제와 정답, 힌트, 테스트 케이스는 수정하지 않았습니다. Lv4·Lv5 난이도 조절과 띄어쓰기·개행 정리는 이후 단계별 문제 제작 요청에 맞춰 진행합니다. 기존 문제당 단일 케이스는 11~12개이며 첫 2개로 예제를 만들고 나머지는 숨은 채점 파일로 검사합니다.

| 레벨 | 선착 승점 | 후착 승점 | 정답 시 solve포인트 |
|---|---:|---:|---:|
| Lv1 | 100 | 50 | 100 |
| Lv2 | 150 | 75 | 150 |
| Lv3 | 200 | 100 | 200 |
| Lv4 | 250 | 125 | 250 |
| Lv5 | 300 | 150 | 300 |

미해결 문제의 승점·solve포인트는 모두 0입니다. 힌트 가격은 문제 유형 50점, 핵심 구조 120점, 현재 코드에 대한 AI 조언 250점입니다. solve포인트는 팀 공동 잔액의 거래 내역에 적립/차감되고, 승점은 별도로 저장됩니다.

## AI 조언 활성화

AI 도움말은 API 키가 없으면 비활성화됩니다. 키가 있으면 **서버 프로세스의 환경 변수**로만 설정하세요. 브라우저 화면이나 코드 파일에 키를 입력하지 않습니다.

```bash
export OPENAI_API_KEY='본인의_API_키'
python server.py
```

PowerShell:

```powershell
$env:OPENAI_API_KEY='본인의_API_키'
py -3 server.py
```

선택적으로 `OPENAI_MODEL` 환경 변수로 코드 조언 모델을 정할 수 있습니다(기본값 `gpt-4.1-mini`). 로고 생성은 `OPENAI_IMAGE_MODEL`(기본값 `gpt-image-1`)을 사용하며, 팀장이 팀명을 저장한 뒤 **로고 후보 3개 만들기**를 누르면 서버가 OpenAI 이미지 생성 API를 한 번 호출합니다. API 키가 없으면 세 후보를 **임시 로고**로 표시하고 선택할 수 있습니다. 키를 설정한 뒤 이미 만들었던 임시 후보를 AI 후보로 바꾸려면 팀장이 팀명 저장 단계에서 이름을 변경해야 합니다. 로고가 이미 확정되었다면 현재 프로토타입에서 재설정할 수 없습니다.

`logo_prompt.txt`에 로고 생성 프롬프트를 별도로 실었습니다. 일반적인 국제 e스포츠 팀 로고의 시각적 특성을 설명하면서 실제 구단의 고유 로고·상표를 복제하지 않도록 지시합니다. 기존 롤드컵 출전팀 로고를 API에 학습시키는 기능은 포함하지 않습니다. AI 조언에는 문제 설명과 현재 코드가 전송되고, 로고 생성에는 팀명이 전송됩니다. 실패한 AI 조언은 포인트를 차감하지 않습니다. 각 호출은 사용 계정의 과금 대상입니다.

## Netlify + Render 배포 준비

1. Git 저장소 루트에 `netlify.toml`과 `render.yaml`을 함께 올립니다. Render Blueprint는 Python 웹 서비스와 1GB 영속 디스크를 설정합니다. Render 서비스의 비밀 환경 변수 `FRONTEND_ORIGIN`에 실제 Netlify 주소(예: `https://my-arena.netlify.app`, 끝 `/` 제외)를 입력합니다. `OPENAI_API_KEY`는 구매 후 Render의 환경 변수에만 등록합니다.
2. Netlify에서 이 저장소를 연결해 배포하면 `netlify.toml`이 `static` 폴더를 게시합니다. 배포 전에 `static/config.js`의 `RUMBLE_API_BASE_URL`을 실제 Render URL(예: `https://code-rumble-api.onrender.com`)로 바꾸고 재배포합니다. 이 파일에 API 키를 넣지 마세요.
3. Render 디스크의 `/var/data/access.json`에서 최초 참가 코드를 운영자만 확인하여 각 참가자에게 개별 전달합니다. 데이터베이스와 코드는 이 디스크에 유지됩니다. `render.yaml`의 유료 `starter` 플랜과 디스크 요금·서비스 URL은 Render 관리 화면에서 확인하세요. `FRONTEND_ORIGIN`은 접속 출처 하나를 정확히 입력합니다.

**공개 서비스 채점 제한:** 이 프로토타입의 로컬 채점기는 제출된 Python 코드를 실행하며 운영체제 수준 격리가 없습니다. `HOST=0.0.0.0`인 Render에서는 `/api/submit`을 의도적으로 차단합니다. 따라서 이 두 배포 설정만으로 공개 대회의 코드 제출·점수 집계는 동작하지 않습니다. 공개 운영 전에는 별도의 격리 채점 서비스 연결, 참가 코드 전달 방식과 인증 강화, 동시성 및 운영 검증이 필요합니다. 로컬에서 `python server.py`로 실행하면 기존 제출 기능을 시험할 수 있습니다. 방화벽이나 프록시로 외부에 공개한 로컬 서버도 안전하지 않습니다.

## 테스트

```bash
python -m unittest discover -s tests -v
```

Node.js가 설치되어 있다면 `node tests/test_frontend.js`로 자동완성·들여쓰기와 종료 화면 전환도 확인할 수 있습니다. 프로그램 자체의 실행에는 Node.js가 필요하지 않습니다.

15개의 모범 풀이가 확장된 채점 케이스를 모두 통과하는지와, 첫 이름 설정·중복 레벨 방지·미선택 레벨 배정·같은 라운드에서 포인트 사용·결승 진출 흐름을 검사합니다.

## 이 프로토타입의 범위

코드 실행에는 시간·메모리 제한이 있지만 운영체제 수준의 보안 격리는 없습니다. **신뢰하지 않는 사람의 코드를 로컬 채점기로 받거나 로컬 서버를 외부 네트워크에 노출하지 마세요.** 실전 행사는 별도 격리 채점기 및 운영 검증이 필요합니다.
